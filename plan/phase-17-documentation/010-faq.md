# 010 -- FAQ (`docs/faq.md`)

## Context

Depends on issue 001. Independent of issues 002-009, but written last among
the content issues (numbered 010) since a good FAQ often surfaces questions
answered more fully elsewhere and should link out rather than duplicate --
easier to write well once the other nine guides exist to link into.

## Scope of this issue

Write `docs/faq.md`: short question/answer pairs, each answer a few
sentences with a link to the deeper guide when one exists (this file should
rarely be the deepest source of truth on any topic -- it's a fast-answer
index). Cover, at minimum:

1. **"Do I need a provider to use typetrack?"** No -- `provider` is
   optional, defaults to `noopProvider` (cite `src/index.ts`'s
   `createAnalytics`: `normalizeProviders(options.provider ?? noopProvider)`).
   Useful for local dev/testing before wiring a real vendor.
2. **"What happens if I call `identify()`/`group()`/`alias()` against a
   provider that doesn't support it?"** A one-time `console.warn`, the call
   is otherwise a no-op -- never a thrown error, never a silent wrong call.
   Cite `isCapabilitySupported()` in `src/index.ts`.
3. **"Can I send the same event to multiple providers with different
   payloads?"** Not directly -- `provider: [...]` fans out the *same*
   `CanonicalEvent` to every listed provider (each adapter does its own
   event/property translation internally). Use `enrichmentMiddleware`/a
   custom `before()` if a provider genuinely needs different data, or
   `redactMiddleware`/`piiFilterMiddleware` if it needs *less* data. Link
   `docs/middleware.md`.
4. **"Why does `track()` sometimes return `void` and sometimes a
   `Promise`?"** The zero-middleware, single-provider fast path returns
   whatever the provider's own `track()` returns (often synchronous `void`
   for a simple provider); registering middleware or using a multi-provider
   array always returns a `Promise`. Link `docs/performance.md`'s "zero-cost
   when unused" section, which documents this exact fast-path guarantee.
5. **"Is validation required?"** No -- `schemas` is optional per event; an
   event with no `schemas[event]` entry is forwarded unvalidated. `validate:
   false` disables validation instance-wide (e.g. for production bundle
   stripping). Link `docs/cookbook.md`.
6. **"What TypeScript version / toolchain does typetrack need?"** State the
   real, current toolchain from CLAUDE.md: Bun (install + test runner),
   `tsgo` for fast typechecking, `typescript` 6.x (`tsc`) as the emit/
   source-of-truth compiler. `zod` is an optional peer dependency (only
   needed if using `schemas`) -- cite root `package.json`'s
   `peerDependenciesMeta.zod.optional`.
7. **"Does typetrack work in Cloudflare Workers / Vercel Edge / Bun /
   Deno?"** Depends on the adapter -- core itself is runtime-agnostic; each
   provider adapter declares its own verified `capabilities.runtimes` array
   (cite one example from each: GA4 `["node","browser","edge","bun","deno"]`,
   PostHog SDK `["node","edge","bun","deno"]` (no browser -- explain why,
   briefly, per that adapter's own researched comment), Segment SDK
   `["node","bun","deno"]` (no browser/edge -- explain why)). Link `docs/
   providers/*.md` for the full per-adapter detail.
8. **"How do I test my analytics code without hitting a real vendor?"**
   `noopProvider` for "accept everything, do nothing"; a hand-written fake
   `AnalyticsProvider` object for asserting on calls; `typetrack dev` (the
   local dev server + CLI) for a real local endpoint that validates against
   your real schemas and shows events live. Cite `src/providers/index.ts`'s
   `noopProvider` and `src/cli/dev.ts`.
9. **"Is typetrack published to npm yet?"** Answer honestly from the real,
   current state (check `plan/CHANGELOG.md`/`plan/ROADMAP.md` for whether
   Phase 21 "npm publish CI" has landed as of this issue being written) --
   do not claim a publish status that isn't yet true.
10. **"Where do I report a bug / ask a question not covered here?"** Point
    at whatever this repo's real, current contribution/issue-tracking
    convention is (check the repo root/`.github/` for a `CONTRIBUTING.md`
    or issue template before writing this answer -- if none exists, say so
    plainly rather than inventing a process, e.g. "open a GitHub issue on
    this repository").

The implementor may add further questions genuinely useful given what was
learned while writing issues 002-009, but should not pad the list.
