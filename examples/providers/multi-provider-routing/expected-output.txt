Notes on what's happening above, per event, and why:
- "Checkout Started" (context: development): matches
  analytics-warehouse's `include`, is not excluded by marketing-pixel's
  `exclude`, and matches debug-console's `predicate` -- all 3 always receive
  it. full-featured only receives it when this simulated user's anonymousId
  samples "in" at the 0.5 rate (user-B here, not user-A).
- "Purchase Completed" (context: production): same include/exclude outcome
  as "Checkout Started", but debug-console's predicate fails (environment is
  "production", not "development") -- debug-console never logs this event.
- "debug.cache_miss" (context: development): excluded by marketing-pixel's
  `exclude` (`/^debug\./` matches), not matched by analytics-warehouse's
  `include` (not a commerce event name) -- only debug-console (predicate
  matches) and, when sampled in, full-featured receive it.
- "Page Viewed" (no context at all): not commerce (fails `include`), not
  debug-namespaced (passes `exclude`), and has no `context.environment` to
  satisfy debug-console's `predicate` -- only marketing-pixel (and, when
  sampled in, full-featured) receive it.
- `identify()`: always fans out to all 4 providers unconditionally, which is
  why every provider (including analytics-warehouse and debug-console, which
  received 0-2 of the 4 track() calls above) logs exactly one identify line.
- `flush()`: likewise reaches all 4 providers unconditionally, exactly once
  each (this flow never calls `destroy()` -- see the README).
- Call order for "Checkout Started" is ascending by each entry's `priority`
  (full-featured=0, marketing-pixel=10, debug-console=20,
  analytics-warehouse=30) -- note this is the *opposite* of the array
  declaration order in `index.ts` (analytics-warehouse is declared first,
  full-featured last), which is exactly the point: `priority` controls call
  order, not array position.
