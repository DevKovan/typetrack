Notes on what's happening above:
- The old call site (`analytics.track("checkout_started", { cartValue })`)

- The deprecation warning line (`typetrack: event "checkout_started" is
  deprecated -- use "Checkout Started" instead. Planned removal:
  2027-01-01.`) prints exactly ONCE, even though the old call site is
  invoked 3 times -- typetrack's warn-once-per-event-name behavior, keyed
  per `Analytics` instance for that instance's whole lifetime.

  RESOLVED name, `"Checkout Started"` -- never the original
  `"checkout_started"` -- because a `deprecatedEvents` entry with a
  `replacement` auto-redirects every downstream use (schema lookup,
  `CanonicalEvent.name`, provider dispatch) to the new name. This is what
  makes the whole migration a one-file `deprecatedEvents` config change,
  not an application-code sweep across every call site.
