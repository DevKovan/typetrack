NOTE: validate:false (Instance B) skips only the RUNTIME check -- it does not, by itself, shrink a production bundle. Instance C's createGuardedAnalytics() additionally guards the `schemas` reference itself behind the same IS_PRODUCTION check -- see README.md's Production notes for why that second guard is required for real bundle-size stripping, and why that's a documented, accepted industry limitation, not a typetrack gap.

Notes on what's happening above:
- Instance A and Instance C behave identically here, because this run's
  IS_PRODUCTION is false (its underlying `resolveValidationConfig(false)`
  call resolves to `{ schemas: eventSchemas, validate: true }`, the same
  configuration Instance A is built with directly).
- Only Instance B demonstrates `validate: false` skipping the runtime check
  -- the malformed payload sails straight through to the stub provider.
- A real production build with `NODE_ENV=production` would make Instance C
  behave like Instance B (schemas/validate both stripped) -- but Instance B
  ALONE is not the production recipe: it never guards the `schemas`
  reference, so `eventSchemas` (and Zod) still get bundled either way. Only
  Instance C's pattern actually gives a real bundler's dead-code elimination
  something to remove.
