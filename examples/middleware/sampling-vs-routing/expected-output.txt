Notes on what's happening above, and why:
- "globally-dropped": this user's anonymousId failed `samplingMiddleware`'s
  0.7 rate gate, in `before()`, before dispatch ever began evaluating either
  provider's routing. Neither `search-analytics-warehouse` (which has no
  per-provider sampling at all) nor `ml-ranking-vendor` received the event --
  a global middleware drop overrides every provider's own routing config,
  unconditionally.
- "vendor-excluded": this user's anonymousId passed the 0.7 global gate (so
  dispatch proceeded), but failed `ml-ranking-vendor`'s own, stricter 0.3
  `ProviderEntry.sampling` gate. `search-analytics-warehouse` (no
  per-provider sampling) still received the event -- per-provider sampling
  only ever excludes the one provider it's configured on, never any other
  provider in the same list.
- "delivered-to-both": this user's anonymousId passed both gates -- both
  providers received the event.
- The 4th mathematically possible boolean combination (vendor received it
  but warehouse didn't) never appears, and can't: both gates key on the same
  underlying `hashToUnitInterval(anonymousId)` value, and 0.3 is strictly
  narrower than 0.7, so passing the stricter per-provider gate always implies
  passing the looser global gate for the same anonymousId.
